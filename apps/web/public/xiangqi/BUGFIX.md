# 第一轮整改说明（P0/P1）

按任务书「第一轮仅进行 P0/P1 单机修复」执行。在原有项目上增量修改，
保留原有规则引擎主体、AI 框架、SVG 棋盘与木质棋子素材，未推倒重写。

## P0-01 点击空白位置无法落子 —— 已修复

**原因**：旧版只有棋子元素挂 click 监听，空白交叉点无元素可点；
另一个 svg 级监听只做"清除选择"，永远无法对空位落子。

**修复**（`js/app.js` + 新增 `js/geom.js`）：

- 全棋盘唯一一个 svg click 监听（事件委托），通过 `getScreenCTM()` 逆变换
  把点击位置换算为棋盘局部坐标，再经 `XQG.cellFromLocal()` 换算行列；
  容差 0.44 格，未命中交叉点返回 null。
- 统一入口 `onCellClick(r, c)` 实现：选中/切换选中己方子、空位移动、
  敌子吃子、非法位置不执行、再点选中子取消选择。
- 删除旧的逐棋子监听与旧的 svg 监听，一次点击只处理一次。
- 换算核心抽成纯逻辑模块 `js/geom.js`，可单测（90 格 × 两种视角往返一致性）。

**验证**：`tests/run-tests.js` T6——炮二平五（空位落子）、红马进空位、红兵进空位、
非法空位不落子、再点取消、翻转后操作。

## P0-02 AI 计算任务干扰新棋局 —— 已修复

**原因**：旧版 `setTimeout` 闭包直连全局棋盘，重新开局后未执行的定时器
会对新棋盘落子。

**修复**（`js/app.js`）：

- 局次版本号 `gameEpoch` + `aiTimer` 句柄：`cancelPendingAI()` 在
  新局/悔棋时递增 epoch 并 clearTimeout。
- AI 回调双重校验（计算前 + 计算后）：epoch 不符 / 已终局 / 回合已换
  → 直接丢弃，不碰棋盘；`aiThinking` 在所有退出路径复位。
- AI 一律在 `XQ.cloneBoard(state.board)` 克隆上计算，绝不污染真实对局。
- AI 无结果/异常时不再判玩家胜：先由真实规则状态决定终局；
  不终局则从合法着法随机兜底一步避免卡死（正常情况下引擎保证有着法时必有结果）。

**验证**：T6——人走一步触发 AI 后 700ms 内连点 3 次"重新开局"，
棋盘保持初始局面、历史为空、回合为红；正向场景 AI 正常应着一手。

## P1-01 棋盘方向错误 —— 已修复

**原因**：旧版 `viewRow(r) = flipped ? 9-r : r`——默认视角把红方底线
（row 0）画在屏幕**顶部**，红方在下/黑方在上的要求落空。

**修复**（`js/geom.js`）：

```
viewRow(r, flipped) = flipped ? r : 9 - r   // 默认：红底线(row0)→屏幕底部
viewCol(c, flipped) = flipped ? 8 - c : c   // 翻转：整体旋转 180°
```

翻转只改渲染与点击映射，绝不修改真实棋盘数组。

**验证**：T4——两种视角 90 格点击换算往返一致；T6——翻转后选中、
走子（左马 (0,1)→(2,2)）正常，翻回后棋盘数组与走子前一致（仅走子改变）。

## P1-02 中文记谱错误 —— 已修复

**原因**：旧版记谱内嵌在 app.js：进退不分红黑（黑方的"进"方向算反）、
马相士斜行子按纵向步数记谱（应记目标纵线）、无同线判重（前中后）。

**修复**（新增 `js/notation.js`，app.js 调用）：

- 纵线编号：红方右侧数起「一~九」（col0=九），黑方右侧数起「1~9」（col0=1）；
  红用汉字、黑用阿拉伯数字（传统谱惯例）。
- 红「进」= row 增大，黑「进」= row 减小；同行「平」。
- 直行子（车炮兵将帅）进退记步数；斜行子（马相象士）记目标纵线。
- 同纵线多枚同类同色子：前/中/后 + 棋子名（红"前"=靠黑方，黑"前"=靠红方）。
- **记谱在走子前的棋盘上生成，随历史保存**（悔棋重放后记录仍正确）。

**验证**：T3——炮二平五、马八进七、相七进五、卒5进1、马8进7、
黑卒过河平走、三车同线「中车进一」、黑方前/后车、炮五进四。

## P1-03 被吃棋子样式不匹配 —— 已修复

**原因**：CSS 选择器写的 `.captured svg`，而 JS 创建的是 `img`，样式从未生效。

**修复**（`css/style.css`）：`.captured img { display:block; width/height:24px;
flex-shrink:0; object-fit:contain; opacity:.9 }`；移动端布局同步收紧
（吃子区 max-width + flex 收缩防溢出）。

**验证**：T6 渲染链路无异常 + 样式规则与实际元素匹配（人工核）。

## P1-04 合法走棋统一入口 —— 已完成

**修复**（`js/engine.js`）：

- `createInitialState()`：`{board, turn, over, winner, reason, version, lastMove}`。
- `safeApplyMove(state, actorSide, move)` 依次校验：对局进行 → 回合 →
  坐标（`Number.isInteger` + 范围）→ 起点归属 → 走法合法（引擎合法着法表内）；
  全部通过才在**克隆棋盘**上落子，返回新状态（version+1），
  错误码 `GAME_OVER / NOT_YOUR_TURN / BAD_COORDS / NOT_YOUR_PIECE / ILLEGAL_MOVE`。
- `onBoard()` 加整数校验（拒绝 0.5、'a'、null 等）。
- 原棋盘永不被客户端操作原地修改（app.js 的 state 全量替换）。
- 单机/联机共用此入口——联机客户端只发 `{fr,fc,tr,tc}`，服务端权威复算。

**验证**：T2——合法走子（炮二平五、马8进7）版本连续；六类错误码逐一命中；
走子后原棋盘逐格比对未变；终局后拒绝。

## P1-05 AI 搜索改进 —— 已完成（Worker 迁移延后）

**修复**（`js/ai.js`）：

- `quiesce()` 区分将军态：被将军时搜**全部**应将着法（搜不出=将死评分），
  不再用静态评价敷衍；非被将军才静态评价 + 仅吃子展开。
- 静态搜索深度上限 `QDEPTH_MAX=8`：连环将军不再无限递归。
- 节点预算 30000 + 时间预算 3s：超限提前截断保留最好结果；
  未搜完的着法轻微降权，优先选完整搜索的。
- AI 出错时恢复 UI（`aiThinking` 复位 + 合法着法兜底），不卡死不误判胜负。

**验证**：T5——开局出着、预算受控、被将军时给出经引擎校验合法的应将着法、
将死方返回 null、自博弈 60 手每步过 `safeApplyMove` 全合法。
